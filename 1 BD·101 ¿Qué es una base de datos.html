01

¿Qué es una base de datos?

⏱ 20 min de lectura
Una base de datos es una colección de datos organizada de tal forma que sea fácil guardarlos, buscarlos, actualizarlos y protegerlos. Piensa en ella como una biblioteca digital donde cada libro está catalogado: no basta con tener los libros, hay que poder encontrarlos rápido.

Primero lo primero: dato ≠ información

Aunque se usan como sinónimos, no son lo mismo. Esta diferencia es la base de todo lo que veremos en el curso:

Concepto¿Qué es?Ejemplo
DatoUn hecho suelto, sin contexto: un número, una palabra, una fecha.38 · "14/02" · "Bogotá"
InformaciónDatos organizados y con contexto, que permiten tomar decisiones.“Valentina tiene 38 °C de temperatura: necesita atención médica”.
💡 Regla para recordarDato + contexto + propósito = información. Una base de datos bien diseñada es la máquina que convierte lo primero en lo segundo.

Ya las usas todos los días (aunque no lo sepas)

Cada vez que haces algo de esto, una base de datos está trabajando por detrás:

Situación cotidiana¿Qué guarda la base de datos?
🎧 Tu plataforma de músicaCanciones, artistas, tus playlists y lo que has escuchado.
🛒 El carrito de una tienda en líneaProductos, precios, tu pedido y tu dirección.
🏥 Una cita médicaTu historial clínico, diagnósticos y tratamientos.
🎓 El boletín de notasEstudiantes, asignaturas y calificaciones.
🏦 El bancoCuentas, movimientos y beneficiarios.

Un viaje rápido en el tiempo

1960s Nacen las primeras bases de datos jerárquicas, como IMS de IBM: los datos se organizaban como un árbol genealógico.
1970 Edgar F. Codd publica el artículo que cambia la historia: propone el modelo relacional (tablas relacionadas). Sigue siendo el rey hasta hoy.
1986 SQL se convierte en estándar ANSI: el idioma universal para hablar con bases de datos.
1990s La web explota y con ella sistemas libres como MySQL y PostgreSQL.
2000s+ Llegan las bases NoSQL (documentos, grafos) y, hoy, bases de datos especializadas incluso para inteligencia artificial.
¿Sabías que…? (3 datos curiosos para romper el hielo)

1️⃣ La palabra SQL se puede pronunciar “secuel” (como en inglés sequel) o letra por letra: “ese-cu-ele”. Las dos son válidas.

2️⃣ Una tarjeta SIM de celular guarda una pequeña base de datos con tus contactos.

3️⃣ “Dato” viene del latín datum, que significa “lo que se da”. Literalmente, algo que se entrega para ser procesado.

02

Piezas fundamentales: tablas, campos y registros

⏱ 25 min de lectura

Una base de datos relacional organiza la información en tablas, como un archivero con carpetas etiquetadas. Mira esta tabla de canciones y luego las etiquetas que la explican:

idtituloartistaduracion_seggenero
PK 1La BicicletaCarlos Vives & Shakira222Vallenato/Pop
2Vivir Mi VidaMarc Anthony252Salsa
3PepasFarruko287Electrónica
Cada columna es un campo: define qué dato se guarda. Cada fila completa es un registro: un elemento concreto. PK: la clave primaria, el identificador único.

El vocabulario oficial

CAMPO = COLUMNA

Campo

Cada “etiqueta” de información que guarda la tabla: titulo, artista, duracion_seg… Todos los registros comparten los mismos campos.

REGISTRO = FILA

Registro

Un elemento completo descrito por sus campos. “Vivir Mi Vida, de Marc Anthony, 252 segundos, Salsa” es un registro.

TIPO

Tipo de dato

La regla que dice qué puede guardar cada campo: números, texto, fechas… (Unidad 04).

PRIMARY KEY

Clave primaria (PK)

El identificador único de cada registro, como la cédula de una persona. Nunca se repite ni puede quedar vacío.

FOREIGN KEY

Clave foránea (FK)

Un campo que apunta a la clave primaria de otra tabla: el puente que las conecta (Unidad 03).

🧠 La analogía de la agendaTu agenda de contactos es una tabla: cada contacto es un registro; nombre, teléfono y correo son los campos; y el número de teléfono funciona casi como una clave primaria (no suele haber dos iguales).

Mini reto relámpago ⚡

Observa de nuevo la tabla canciones y responde antes de abrir la solución:

  • ¿Cuántos campos tiene la tabla?
  • ¿Cuántos registros tiene?
  • ¿Qué campo es la mejor candidata a clave primaria y por qué?
Ver solución del mini reto

• 5 campos: id, titulo, artista, duracion_seg, genero.

• 3 registros: uno por canción.

• La clave primaria ideal es id: es única para cada canción y nunca cambia. ¿Y si usáramos titulo? Problema: dos canciones podrían llamarse igual… ¡por eso existen los id!

03

El modelo relacional: tablas que conversan entre sí

⏱ 30 min de lectura

Una base de datos relacional no es una tabla gigante: es un equipo de tablas pequeñas, cada una experta en un tema, conectadas por claves. Como piezas de rompecabezas que encajan.

¿Por qué no meter todo en una sola tabla?

Imagina una tienda de música que guarda todo junto. Mira lo que pasa cuando vende varias veces al mismo cliente:

pedidoclientetelefonocancion
101Laura Gómez310-555-0001La Bicicleta
102Laura Gómez310-555-0001Pepas
103Laura Gómez310-555-0001Vivir Mi Vida
⚠️ Detecta el problemaEl nombre y teléfono de Laura están repetidos 3 veces. Si Laura cambia de número, habría que actualizar 3 filas… y si se nos olvida una, ¡tendremos datos contradictorios! La solución: separar en tablas y conectarlas.

La solución relacional

CLIENTES

  • PK id
  • nombre
  • telefono
→cliente_id

PEDIDOS

  • PK id
  • FK cliente_id
  • fecha
  • total
→pedido_id

DETALLE

  • FK pedido_id
  • FK cancion_id
  • precio
←cancion_id

CANCIONES

  • PK id
  • titulo
  • FK artista_id

Ahora los datos de Laura viven una sola vez en CLIENTES, y los pedidos solo guardan su cliente_id. Si cambia de teléfono, se actualiza un único registro. Eso es diseñar bien.

Tipos de relaciones

RelaciónSignifica que…Ejemplo
1 : 1Un registro se conecta con exactamente otro.Un usuario ↔ su perfil personal.
1 : NUn registro se conecta con muchos, pero cada uno de esos muchos solo con uno. ¡La más común!Un artista → muchas canciones. Una canción es de un solo artista.
N : MMuchos se conectan con muchos. Se resuelve con una tabla intermedia.Estudiantes ↔ asignaturas: se conectan mediante la tabla MATRÍCULAS.

Las 5 reglas de oro del diseño relacional

  1. Toda tabla necesita una clave primaria.
  2. No repitas datos: referéncialos con claves foráneas.
  3. Cada tabla describe un solo tipo de cosa (clientes, canciones, pedidos…).
  4. Cada campo guarda un solo valor (nada de “teléfonos: 310-555, 311-777”).
  5. Define el tipo de dato de cada campo y respétalo.
¿Sabías que…? El origen del nombre “relacional”

No viene de que las tablas “se relacionen” entre sí (eso es consecuencia). Viene de la teoría de relaciones de la matemática, en la que Codd se basó en 1970. En esa teoría, una tabla se llama formalmente… ¡relación!

04

Tipos de datos y buen diseño

⏱ 20 min de lectura

Cada campo debe declarar qué clase de valor acepta. Es como etiquetar las cajas antes de una mudanza: si guardas fechas en una caja de “líquidos”, todo se derrama.

Los tipos más usados

Tipo¿Qué guarda?Ejemplo válidoÚsalo cuando…
INTEGERNúmeros enteros.25, -3, 0Cantidades, edades, identificadores.
VARCHAR(n)Texto de hasta n caracteres.'Valentina'Nombres, correos, ciudades.
TEXTTexto largo, sin límite práctico.'Érase una vez…'Comentarios, descripciones largas.
DATEUna fecha.'2026-09-16'Fecha de nacimiento, fecha de entrega.
BOOLEANVerdadero o falso.TRUE / FALSE¿Está activo? ¿Ya pagó? ¿Disponible?
DECIMAL(10,2)Números con decimales exactos.19990.50Precios y dinero (¡nunca uses tipos inexactos para dinero!).

Tres reglas prácticas para un diseño sano

Los profesionales hablan de “normalización”. Tú puedes empezar con su versión en lenguaje simple:

❌ ANTES (con problemas)
campovalor
telefonos"310-555, 311-777"
pedido + correo del cliente juntoscorreo repetido en cada pedido
✅ DESPUÉS (corregido)
reglaaplicación
1. Un campo, un valor.Una tabla TELEFONOS con una fila por número.
2. Cada dato vive donde pertenece.El correo vive en CLIENTES; el pedido solo guarda cliente_id.

Regla 3: nada de datos repetidos. Si el país del artista apareciera en cada fila de canciones, al corregirlo tendrías que perseguirlo por toda la tabla. Mejor: el país vive una sola vez en la tabla ARTISTAS.

💬 Frase para memorizar“Todo el dato, solo el dato y nada más que el dato.” Cada pieza de información debe existir una única vez, en el lugar correcto.
Ejercicio guiado: detecta los 3 errores de esta tabla
id_pedidoclienteproductosfecha
1Ana Torres"audífonos, cable USB"16/09/2026
2Ana Torres"teclado"16/09/2026

Solución: ① El nombre “Ana Torres” se repite (debería vivir en una tabla CLIENTES). ② El campo productos guarda varios valores juntos (rompe la regla “un campo, un valor”: debería existir una tabla DETALLE). ③ Falta claridad de tipos y una clave primaria que identifique cada línea del pedido.

05

Hola, SQL: tu primera conversación con la base de datos

⏱ 30 min de lectura

SQL (Structured Query Language, lenguaje estructurado de consultas) es el idioma estándar para pedirle cosas a una base de datos relacional. Piénsalo como pedir en un restaurante: haces un pedido preciso (“una consulta”), la cocina (el motor de la base de datos) lo procesa y te entrega el resultado.

Anatomía de un SELECT

La instrucción más famosa de SQL responde tres preguntas: ¿qué quiero? ¿de dónde? ¿con qué condición?

  consulta_01.sql
SELECT titulo, artista          -- ¿QUÉ columnas quiero?
FROM canciones                  -- ¿DE DÓNDE? (la tabla)
WHERE genero = 'Salsa';         -- ¿CON QUÉ condición?

Aplicada a nuestra tabla canciones de la Unidad 02, el resultado sería:

tituloartista
Vivir Mi VidaMarc Anthony

También puedes agregar datos: INSERT

  consulta_02.sql
INSERT INTO canciones (titulo, artista, duracion_seg, genero)
VALUES ('Onda Tropical', 'Los del Mar', 204, 'Pop');

Nota los detalles de estilo: los textos van entre comillas simples 'así', los números no, y cada instrucción termina en punto y coma ;

Traductor SQL ↔ lenguaje cotidiano

Como lo dirías túComo lo dice SQL
“Dame los títulos de las canciones de salsa.”SELECT titulo FROM canciones WHERE genero = 'Salsa';
“¿Cuántas canciones hay en total?”SELECT COUNT(*) FROM canciones;
“Muéstrame todo de las canciones que duren más de 250 segundos.”SELECT * FROM canciones WHERE duracion_seg > 250;

Relámpago SQL ⚡

Escribe la consulta que devuelva todas las columnas de las canciones que duren más de 240 segundos. Inténtalo antes de abrir la pista.

Ver solución 
SELECT * FROM canciones WHERE duracion_seg > 240;

El * significa “todas las columnas”. De nuestra tabla de ejemplo devolvería los registros 2 y 3 (252 y 287 segundos).

🚀 ¿Y ahora qué?Ya conoces las dos operaciones más usadas: SELECT para preguntar y INSERT para agregar. Con UPDATE y DELETE completarás el famoso CRUD (Crear, Leer, Actualizar, Borrar)… ¡ese será tu siguiente nivel!

A2

De la historia al modelo: la veterinaria “Huellitas”

⏱ 20 min · individual

“La veterinaria Huellitas quiere organizarse. De cada mascota registran nombre, especie y fecha de nacimiento; cada mascota tiene un dueño, del que anotan nombre, teléfono y correo. Cada visita registra la fecha, el motivo y el costo.”

Tu misión: dibuja las tablas necesarias, escribe sus campos y marca con PK y FK las claves.

✏️ Diseña aquí tus tablas (o en tu cuaderno): campos, tipos y claves PK / FK.
💡 Pista

Hay tres “cosas” diferentes de las que se habla: dueños, mascotas y visitas. Cada una merece su propia tabla. ¿Cuál depende de cuál?

🔍 Guía de respuesta

Dueños (id PK, nombre, telefono, correo)

Mascotas (id PK, nombre, especie, fecha_nacimiento, dueno_id FK)

Visitas (id PK, mascota_id FK, fecha, motivo, costo)

Relaciones: un dueño tiene muchas mascotas (1:N); una mascota tiene muchas visitas (1:N). ¿Permitirías que una mascota tuviera dos dueños? ¡Buen debate para la clase! (pista: N:M).

A3

Tipos de datos para la biblioteca

⏱ 15 min · individual

Vamos a crear la tabla LIBROS. Para cada campo, escribe el tipo de dato más adecuado (INTEGER, VARCHAR, DATE, BOOLEAN, DECIMAL…) y justifica tu elección en una frase.

Campo¿Qué guarda?Tu tipo propuesto
idNúmero único de cada libro.___________
tituloEl nombre del libro.___________
año_publicacionEl año en que se publicó.___________
precioLo que cuesta reponerlo.___________

🔍 Guía de respuesta

id → INTEGER (PK) · titulo → VARCHAR(150) · año_publicacion → INTEGER o DATE · precio → DECIMAL(10,2) · disponible → BOOLEAN. Se acepta justificar otras opciones válidas (p. ej. DATE para el año si se guarda la fecha completa).

A4

Escribe la consulta

⏱ 15 min · individual

Usando la tabla canciones de la Unidad 02, traduce cada frase a SQL:

  1. “Dame los títulos de las canciones de género 'Vallenato/Pop'.”
  2. “Muéstrame las canciones que duren 250 segundos o menos.”
  3. “Dame todos los datos de las canciones de Marc Anthony.”
✏️ Escribe aquí tus tres consultas SELECT … FROM … WHERE …
🔍 Guía de respuesta 
-- 1
SELECT titulo FROM canciones WHERE genero = 'Vallenato/Pop';
-- 2
SELECT titulo, artista FROM canciones WHERE duracion_seg <= 250;
-- 3
SELECT * FROM canciones WHERE artista = 'Marc Anthony';

En la 2 también se acepta SELECT *. Lo importante: comillas para texto, números sin comillas y el <= bien escrito.

A5

🏆 Reto integrador: la tienda escolar

⏱ 40 min · equipos de 3–4

El colegio abrirá una pequeña tienda y les encargó diseñar su base de datos. Se venden productos (con nombre, precio y cantidad en bodega) y cada venta registra la fecha, quién compró y qué productos llevó.

Entregables del equipo:

  • Diseño de mínimo 3 tablas con sus campos y tipos de dato.
  • Claves PK y FK claramente marcadas + flechas que muestren las relaciones.
  • 2 consultas SQL: una con WHERE y otra contando registros.
  • El diseño presentado en una hoja, cartelera o diapositiva (¡pongan nombre al diseño!).
✏️ Espacio de borrador del equipo: tablas, relaciones y consultas.
💡 Pista

Piensa en PRODUCTOS, VENTAS y una tabla DETALLE_VENTA que conecte ambas (relación N:M). ¿Por qué no basta con guardar los productos dentro de la venta como un texto?

Glosario de bolsillo

Consulta rápida
Base de datos
Colección organizada de datos, fácil de consultar y actualizar.
Campo
Columna de una tabla; define un tipo de dato (nombre, precio…).
Registro
Fila completa de una tabla; un elemento concreto.
Clave primaria (PK)
Identificador único de un registro. No se repite ni puede faltar.
Clave foránea (FK)
Campo que referencia la PK de otra tabla; crea la relación.
Relación
Vínculo entre tablas: 1:1, 1:N o N:M.
SQL
Lenguaje estándar para consultar bases de datos relacionales.
Consulta (query)
Petición escrita en SQL que la base de datos responde con resultados.
Tipo de dato
Regla que define qué valores acepta un campo (número, texto, fecha…).
Motor de BD
El software que guarda los datos y procesa tus consultas (MySQL, PostgreSQL…).
Normalización
Técnicas para organizar tablas y evitar datos repetidos o contradictorios.
CRUD
Las 4 operaciones básicas: Crear, Leer, Actualizar y Borrar.
