⏱ 15 min de lectura

En el mundo de las bases de datos hay dos piezas que siempre trabajan juntas:

Pieza¿Qué es?Analogía

02

Las familias de SQL: el mapa del idioma

⏱ 15 min de lectura

SQL no es un solo comando: es un idioma con “familias” de comandos, cada una con un oficio. Conocer el mapa te dirá siempre en qué parte del curso estás parado.

FamiliaSignificadoComandos estrellaOficio¿Cuándo la veremos?
DDLData Definition LanguageCREATE · ALTER · DROPConstruye y modifica la estructura (bases y tablas).Esta entrega 🚧
DMLData Manipulation LanguageINSERT · UPDATE · DELETEMueve y transforma los datos dentro de la estructura.BD·107
DQLData Query LanguageSELECTPregunta y obtiene resultados.BD·108 y BD·109
DCLData Control LanguageGRANT · REVOKEDa y quita permisos.Más adelante
TCLTransaction Control LanguageBEGIN TRAN · COMMIT · ROLLBACKAgrupa cambios en transacciones seguras.Más adelante
🤓 Nota de puristasAlgunos libros agrupan SELECT dentro de DML. Es válido; aquí lo llamamos DQL para que el mapa sea más claro. Lo importante: primero se construye la casa (DDL), luego se vive en ella (DML), y luego se pregunta por ella (DQL).
El orden natural del trabajo con bases de datos: DDL crea → DML alimenta y modifica → DQL pregunta. Este tutorial sigue exactamente ese camino.

Analogía para no olvidarlo

Piensa en un cuaderno nuevo:

  • DDL: comprar el cuaderno, dibujar las tablas y ponerles títulos. (CREATE TABLE)
  • DML: escribir, corregir con corrector o arrancar páginas. (INSERT, UPDATE, DELETE)
  • DQL: leerlo y buscar información. (SELECT)
03

Primer paso: CREATE DATABASE

⏱ 20 min práctica

Antes de escribir: las reglas de los nombres

  • Empieza siempre con una letra (nada de números o símbolos al inicio).
  • Sin espacios ni caracteres especiales: usa guion bajo (tienda_db, nunca tienda db).
  • Evita palabras reservadas del idioma (table, select, order…).
  • Convención del curso: minúsculas con guiones bajos, y el sufijo _db para bases de datos.

El script

  crear_base.sql
-- 1. Crear la base de datos
CREATE DATABASE tienda_db;
GO
-- 2. "Entrar" en ella: le dice al motor dónde trabajar
USE tienda_db;
GO
Command(s) completed successfully.

Verifica en el Object Explorer: dentro de Databases ahora aparece tienda_db. Ya existe tu primera base de datos.

🧩 ¿Qué es GO?GO no es una instrucción SQL: es la señal con la que SSMS entiende “ejecuta el lote de arriba antes de seguir”. Se usa después de CREATE DATABASE porque el USE necesita que la base ya exista para poder entrar en ella.

Si algo sale mal…

Msg 1801, Level 16, State 3 — Database 'tienda_db' already exists. Choose a different database name.

Traducción: esa base ya existe. Tienes dos caminos: usar otro nombre, o borrarla primero (veremos DROP DATABASE en la Unidad 05). Los errores en SQL no son fracasos: son mensajes del motor pidiéndote precisión.

Segundo paso: CREATE TABLE y los tipos de datos

⏱ 30 min práctica

Con la base creada y activa, vamos a construir la tabla productos de la tienda escolar. La estructura básica es:

  sintaxis
CREATE TABLE nombre_tabla (
    columna1  TIPO,
    columna2  TIPO,
    columna3  TIPO
);

Los tipos de datos más usados en SQL Server

Tipo¿Qué guarda?EjemploÚsalo para…
INTNúmeros enteros.25, -3Cantidades, edades, identificadores.
DECIMAL(10,2)Decimales exactos (10 dígitos en total, 2 de ellos decimales).19990.50Dinero. Siempre.
VARCHAR(80)Texto de longitud variable hasta 80 caracteres.'Empanada'Nombres, descripciones cortas.
NVARCHAR(80)Como VARCHAR, pero con soporte Unicode completo.'Nandú'Textos con caracteres internacionales.
CHAR(3)Texto de longitud fija (rellena con espacios).'COL'Códigos de tamaño siempre igual.
DATEFecha sin hora.'2026-09-16'Fecha de nacimiento, de vencimiento.
DATETIME2Fecha con hora.'2026-09-16 14:30:00'Eventos, registros con hora exacta.
BIT0 ó 1 (el “booleano” de SQL Server).1 / 0Banderas: ¿activo?, ¿vacunado?, ¿pagó?
⚠️ Dos clásicos de examen① Para dinero nunca uses tipos aproximados (como FLOAT): DECIMAL es exacto. ② En SQL Server el “verdadero/falso” es BIT: se escribe 1 (sí) o 0 (no), sin comillas.

Nuestra tabla productos, columna por columna

  crear_productos.sql
CREATE TABLE productos (
    id                INT IDENTITY(1,1),  -- número generado solo: inicia en 1, sube de 1 en 1
    nombre            VARCHAR(80),          -- texto de hasta 80 caracteres
    precio            DECIMAL(10,2),       -- dinero, exacto, 2 decimales
    cantidad          INT,                  -- unidades en bodega
    fecha_vencimiento DATE,                 -- solo fecha, sin hora
    activo            BIT                   -- 1 = se vende, 0 = no
);

Ejecuta con F5 y revisa Messages:

Command(s) completed successfully.

En el Object Explorer: tienda_db → Tables → dbo.productos. El prefijo dbo es el esquema, algo así como la “carpeta” donde vive la tabla (dbo = database owner, la carpeta por defecto).

⚙ Sobre IDENTITY(1,1)Cuando insertemos filas no escribiremos el id: el motor lo asigna solo (1, 2, 3…). Es el candidato perfecto para la clave primaria, que convertiremos oficialmente en PK en la próxima entrega (BD·104) con las restricciones.

05

Inspeccionar, alterar y borrar (con responsabilidad)

⏱ 20 min práctica

Ver la estructura que creaste

  inspeccionar.sql
EXEC sp_columns 'productos';   -- lista de columnas y sus tipos
EXEC sp_help    'productos';   -- ficha completa: columnas, identidad, etc.
SELECT * FROM productos;         -- ver los datos (aún está vacía)

El último SELECT devolverá los encabezados de las columnas y el mensaje (0 rows affected): normal, todavía no hay datos. También puedes hacerlo con el ratón: clic derecho sobre la tabla → Design.

Agregar una columna sin botar la tabla: ALTER TABLE

  alterar.sql
ALTER TABLE productos
ADD descripcion VARCHAR(150);   -- una columna nueva al final
Command(s) completed successfully.

La prueba de vida (un adelanto de DML)

Para confirmar que la tabla funciona de verdad, insertemos un registro de prueba. No listamos id: IDENTITY lo genera solo. (INSERT a fondo será el tema de BD·107.)

  prueba_de_vida.sql
INSERT INTO productos (nombre, precio, cantidad, fecha_vencimiento, activo)
VALUES ('Gaseosa 400 ml', 3500, 48, '2026-12-15', 1);

SELECT * FROM productos;   -- ahora sí: 1 fila, con id = 1 ⚙

Borrar: el poder y la responsabilidad

  borrar.sql
-- Borrar una tabla (si existe): seguro y sin errores si no existe
DROP TABLE IF EXISTS productos;

-- Borrar TODA una base de datos: primero hay que "salir" de ella
USE master;
GO
DROP DATABASE tienda_db;
🚨 Regla de oroDROP DATABASE es irreversible y no pide confirmación. Además, SQL Server no te deja borrar una base mientras estés “dentro” de ella: por eso primero USE master. Antes de ejecutarlo, respira y relee el nombre.

Cazador de errores · en papel

⏱ 15 min · parejas

Este script tiene 5 errores. Encuéntralos y explica por qué cada uno falla:

  script_con_errores.sql — ¡no lo ejecutes así!
CREATE DATABASE tienda db;
USE tienda;

CREATE TABLE productos (
    id       INT IDENTITY(1,1),
    nombre   VARCAR(80),
    precio   DOUBLE,
    cantidad INT
✏️ Anota aquí los 5 errores y su explicación.
💡 Pista

Revisa: un nombre, el USE, dos tipos de datos y el final del CREATE TABLE.

🔍 Solución

① tienda db tiene espacio: los nombres no llevan espacios. ② USE tienda apunta a una base que no existe (se llama diferente). ③ VARCAR está mal escrito: es VARCHAR. ④ DOUBLE no existe en SQL Server (y para dinero se usa DECIMAL). ⑤ Falta cerrar el paréntesis ) del CREATE TABLE.

-- Versión corregida
CREATE DATABASE tienda_db;
GO
USE tienda_db;
GO
CREATE TABLE productos (
    id       INT IDENTITY(1,1),
    nombre   VARCHAR(80),
    precio   DECIMAL(10,2),
    cantidad INT
);

⏱ 35 min · parejas

“El refugio Patitas necesita registrar sus mascotas: un código automático para cada una, su nombre, la especie, la fecha de nacimiento, el peso en kilogramos (con decimales), si ya está vacunada y la fecha en que llegó al refugio.”

Sigue estos 5 pasos y guarda cada evidencia en tu archivo .sql:

1

Diseña la ficha

Lista los 7 campos y decide el tipo SQL Server de cada uno (escríbelo como comentario en tu script).

2

Crea la estructura

refugio_db + tabla mascotas, con todo y sus GO.

3

Verifica

Ejecuta EXEC sp_columns 'mascotas'; y comprueba que coincide con tu ficha.

4

Prueba de vida

Inserta dos mascotas (recuerda: sin la columna id; BIT con 1 o 0; fechas entre comillas simples).

✏️ Espacio de borrador: ficha de tipos y script.
💡 Pista

Peso con decimales → DECIMAL(5,2) alcanza hasta 999.99 kg. Dos fechas distintas (nacimiento y llegada) → dos campos DATE. ¿Vacunada? → BIT.

🔍 Solución completa 
-- Paso 1 y 2: estructura

GO
USE refugio_db;
GO
CREATE TABLE mascotas (
    id               INT IDENTITY(1,1),  -- código automático
    nombre           VARCHAR(60),
    especie          VARCHAR(40),
    fecha_nacimiento DATE,
    peso_kg          DECIMAL(5,2),
    vacunada         BIT,
    fecha_ingreso    DATE
);

-- Paso 3: verificar
EXEC sp_columns 'mascotas';

-- Paso 4: prueba de vida
INSERT INTO mascotas (nombre, especie, fecha_nacimiento, peso_kg, vacunada, fecha_ingreso)
VALUES ('Firulais', 'Perro', '2023-04-10', 12.5, 1, '2026-08-01');

INSERT INTO mascotas (nombre, especie, fecha_nacimiento, peso_kg, vacunada, fecha_ingreso)
VALUES ('Misifú', 'Gato', '2024-11-02', 3.8, 0, '2026-09-05');

-- Paso 5: ver el resultado
SELECT * FROM mascotas;

Resultado esperado: 2 filas con id 1 y 2 asignados por IDENTITY. Si Firulais llega a vacunarse, su BIT cambiará… pero eso lo haremos con UPDATE en BD·107. 😉

Mini glosario de esta entrega

Consulta rápida
Motor de base de datos
Software que almacena los datos y ejecuta las instrucciones (aquí: SQL Server).
SSMS
SQL Server Management Studio: el cliente gráfico para escribir consultas y administrar el servidor.
Script
Archivo de texto con instrucciones SQL, normalmente con extensión .sql.
Lote (batch) / GO
Grupo de instrucciones que se envían juntas al motor; GO marca el fin de un lote en SSMS.
Esquema dbo
“Carpeta” predeterminada donde se crean las tablas en SQL Server (dbo = database owner).
IDENTITY(inicio, incremento)
Propiedad que hace que SQL Server genere automáticamente valores numéricos únicos para una columna.
base master
Base de datos del sistema; se usa como “punto neutro”, por ejemplo antes de borrar otra base.
sp_columns / sp_help
Procedimientos almacenados del sistema que describen la estructura de una tabla.
