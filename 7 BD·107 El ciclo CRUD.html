01

El ciclo CRUD: las cuatro operaciones fundamentales

⏱ 15 min de lectura
CRUD es el acrónimo de las cuatro operaciones básicas que puedes hacer con los datos: Create (crear), Read (leer), Update (actualizar) y Delete (borrar). Todo sistema de información, desde una tienda escolar hasta un banco, se basa en estas cuatro operaciones.
OperaciónComando SQLQué hace
CreateINSERTAgrega nuevas filas a una tabla.
ReadSELECTLee y consulta los datos (lo verás a fondo en BD·108).
UpdateUPDATEModifica filas existentes.
DeleteDELETEElimina filas existentes.

La regla de oro del orden con FK

Cuando tienes tablas relacionadas, el orden de las operaciones no es opcional:

OperaciónOrden correctoPor qué
INSERTPrimero el padre, después el hijo.El hijo necesita que el padre exista para poder apuntar a su PK.
DELETEPrimero el hijo, después el padre.No puedes borrar al padre mientras los hijos lo referencien (a menos que uses CASCADE).
💡 AnalogíaPiensa en construir y demoler una casa: primero pones los cimientos y luego las paredes (INSERT: padre → hijo). Para demoler, primero quitas las paredes y luego los cimientos (DELETE: hijo → padre). Si lo haces al revés, todo se derrumba.
02

INSERT: crear nuevos datos

⏱ 25 min práctica

INSERT simple: una fila a la vez

  insert_simple.sql
-- Insertar una categoría (tabla padre)
INSERT INTO categorias (nombre)
VALUES ('Bebidas');

-- Insertar un producto (tabla hijo) apuntando a la categoría existente
INSERT INTO productos (nombre, categoria_id, precio, cantidad)
VALUES ('Gaseosa 400 ml', 1, 3500, 48);
(1 row affected)

INSERT múltiple: varias filas en una sola instrucción

  insert_multiple.sql
INSERT INTO categorias (nombre)
VALUES ('Fritos'),
       ('Snacks'),
       ('Dulces');
(3 rows affected)

INSERT omitiendo columnas con DEFAULT

Si una columna tiene DEFAULT, no necesitas incluirla. SQL Server pone el valor automáticamente:

-- La columna activo tiene DEFAULT 1, así que la omitimos
INSERT INTO productos (nombre, categoria_id, precio, cantidad)
VALUES ('Empanada', 2, 2500, 30);
-- activo queda en 1 automáticamente ✔

INSERT con NULL explícito

Si una columna admite NULL y quieres dejarla vacía a propósito:

-- Supongamos que categorias tiene una columna descripcion que admite NULL
INSERT INTO categorias (nombre, descripcion)
VALUES ('Bebidas', NULL);
💡 IDENTITY no se insertaNunca incluyas la columna IDENTITY en el INSERT. SQL Server la genera sola. Si lo intentas, obtendrás un error.

INSERT con SELECT: copiar datos de otra tabla

-- Copiar todos los productos activos a una tabla de respaldo
INSERT INTO productos_respaldo (nombre, categoria_id, precio, cantidad)
SELECT nombre, categoria_id, precio, cantidad
FROM productos
WHERE activo = 1;
🤓 ¿Cuándo se usa esto?Para respaldos, migraciones o para llenar una tabla de resumen con datos ya existentes. Es una herramienta poderosa en la vida real.
03

UPDATE: modificar datos existentes

⏱ 25 min práctica

La sintaxis correcta: siempre con WHERE

  update_con_where.sql
-- Subir el precio de la Gaseosa (id = 1)
UPDATE productos
SET precio = 3800
WHERE id = 1;
(1 row affected)

UPDATE con expresiones

-- Aumentar todos los precios en un 10%
UPDATE productos
SET precio = precio * 1.10
WHERE categoria_id = 1;

UPDATE con múltiples columnas

-- Actualizar precio y cantidad al mismo tiempo
UPDATE productos
SET precio = 2700,
    cantidad = 35
WHERE nombre = 'Empanada';

⚠️ El desastre clásico: UPDATE sin WHERE

¿Qué pasa si olvidas el WHERE?

-- ⚠️ PELIGRO: esto afecta TODAS las filas
UPDATE productos
SET precio = 0;
(N rows affected) — ¡Todas las filas fueron actualizadas!

Acabas de poner todos los productos a precio cero. No hay error de sintaxis: SQL Server ejecuta exactamente lo que le pediste. El problema es que le pediste algo que no querías.

🚨 Regla de supervivenciaAntes de ejecutar un UPDATE, escribe primero el SELECT equivalente para ver exactamente qué filas se verán afectadas: 
-- Paso 1: verificar qué filas se modificarán
SELECT * FROM productos WHERE id = 1;

-- Paso 2: si el resultado es correcto, ejecuta el UPDATE
UPDATE productos SET precio = 3800 WHERE id = 1;
Esta costumbre te salvará de muchos desastres en la vida real.
04

DELETE y TRUNCATE: eliminar datos

⏱ 20 min práctica

DELETE con WHERE: borrar filas específicas

  delete_con_where.sql
-- Borrar el producto con id = 3
DELETE FROM productos
WHERE id = 3;
(1 row affected)

⚠️ DELETE sin WHERE: vaciar la tabla

-- ⚠️ PELIGRO: borra TODAS las filas
DELETE FROM productos;
(N rows affected) — La tabla quedó vacía.

La estructura de la tabla sigue existiendo, pero no tiene datos. Y el contador IDENTITY no se reinicia: el próximo id seguirá desde donde quedó.

TRUNCATE TABLE: vaciar y reiniciar

-- Vaciar la tabla y reiniciar el IDENTITY a 1
TRUNCATE TABLE productos;
CaracterísticaDELETE FROM tablaTRUNCATE TABLE tabla
¿Se puede filtrar con WHERE?SíNo (borra todo)
¿Reinicia el IDENTITY?NoSí (vuelve a 1)
¿Respeta las FK?Sí (puede fallar si hay hijos)No (falla si hay FK apuntando a esta tabla)
¿Es más rápido?Más lento (fila por fila)Más rápido (operación interna)
🚨 Regla de supervivencia (otra vez)Antes de ejecutar un DELETE, escribe primero el SELECT equivalente para verificar qué filas se borrarán. La misma regla que con UPDATE.
05

El orden con FK: INSERT padre→hijo, DELETE hijo→padre

⏱ 15 min práctica

INSERT: primero el padre

Intentemos insertar un producto antes de que exista su categoría:

-- ⚠️ La categoría 999 no existe
INSERT INTO productos (nombre, categoria_id, precio, cantidad)
VALUES ('Producto fantasma', 999, 1000, 5);
Msg 547 — The INSERT statement conflicted with the FOREIGN KEY constraint "FK_productos_categoria".

La solución correcta: insertar primero la categoría, y luego el producto.

-- ✔ Orden correcto
INSERT INTO categorias (nombre) VALUES ('Bebidas');   -- id = 1
INSERT INTO productos (nombre, categoria_id, precio, cantidad)
VALUES ('Gaseosa', 1, 3500, 48);

DELETE: primero el hijo

Intentemos borrar una categoría que tiene productos asociados:

-- ⚠️ Hay productos que apuntan a esta categoría
DELETE FROM categorias WHERE id = 1;
Msg 547 — The DELETE statement conflicted with the REFERENCE constraint "FK_productos_categoria".

La solución correcta: borrar primero los productos hijos, y luego la categoría.

-- ✔ Orden correcto
DELETE FROM productos WHERE categoria_id = 1;   -- borrar hijos
DELETE FROM categorias WHERE id = 1;            -- borrar padre
💡 La alternativa: CASCADESi definiste la FK con ON DELETE CASCADE, SQL Server borra automáticamente los hijos cuando borras el padre. Es más cómodo, pero también más peligroso: asegúrate de que realmente quieres ese comportamiento.
06

Transacciones: el botón de deshacer de SQL Server

⏱ 20 min práctica

¿Qué pasa si estás haciendo varios cambios y a mitad de camino algo sale mal? Una transacción agrupa varias instrucciones DML en una sola unidad: o se ejecutan todas, o no se ejecuta ninguna.

  transaccion.sql
-- Iniciar la transacción
BEGIN TRAN;

-- Operación 1: insertar un pedido
INSERT INTO pedidos (cliente_id, total)
VALUES (1, 5500);

-- Operación 2: insertar el detalle
INSERT INTO detalle_pedido (pedido_id, producto_id, cantidad, precio_unitario)
VALUES (1, 1, 1, 3500);

-- Si todo salió bien, confirmar los cambios
COMMIT;

-- Si algo salió mal, deshacer todo
-- ROLLBACK;
ComandoQué hace
BEGIN TRANInicia la transacción. A partir de aquí, los cambios son provisionales.
COMMITConfirma todos los cambios. Ya no se pueden deshacer.
ROLLBACKDeshace todos los cambios desde el BEGIN TRAN. Como si nunca hubieran ocurrido.
🤓 ¿Cuándo se usa esto?En operaciones que involucran varias tablas y que deben ser atómicas: o se completan todas, o no se completa ninguna. El ejemplo clásico: una transferencia bancaria (restar de una cuenta y sumar en otra). Si falla la segunda operación, hay que deshacer la primera. En este curso lo usaremos de forma introductoria; lo dominarás en un curso más avanzado.

UPDATE y DELETE seguros · parejas

⏱ 25 min

Con los datos insertados en E2, realiza las siguientes modificaciones. Para cada una, escribe primero el SELECT de verificación antes de ejecutar el UPDATE o DELETE:

  • Sube el precio de la Gaseosa de 3500 a 3800.
  • Aumenta en un 10% el precio de todos los productos de la categoría Fritos.
  • Actualiza la cantidad de Empanadas de 30 a 25.
  • Borra el producto Café (cantidad = 0).
  • Intenta borrar la categoría Bebidas (debe fallar si hay productos asociados).
✏️ Espacio para tu script, con los SELECT de verificación incluidos.
💡 Pista

El último DELETE debe fallar con Msg 547 porque hay productos que apuntan a esa categoría. Para borrarla, primero borra los productos hijos.

🔍 Solución 
-- 1. Subir precio de la Gaseosa
SELECT * FROM productos WHERE id = 1;   -- verificar
UPDATE productos SET precio = 3800 WHERE id = 1;

-- 2. Aumentar 10% los Fritos
SELECT * FROM productos WHERE categoria_id = 2;   -- verificar
UPDATE productos SET precio = precio * 1.10 WHERE categoria_id = 2;

-- 3. Actualizar cantidad de Empanadas
SELECT * FROM productos WHERE nombre = 'Empanada';   -- verificar
UPDATE productos SET cantidad = 25 WHERE nombre = 'Empanada';

-- 4. Borrar el Café
SELECT * FROM productos WHERE nombre = 'Café';   -- verificar
DELETE FROM productos WHERE nombre = 'Café';

-- 5. Intentar borrar la categoría Bebidas (fallará)
DELETE FROM categorias WHERE nombre = 'Bebidas';
-- Msg 547: hay productos que apuntan a esta categoría

🏆 Reto integrador: un día en la tienda escolar

⏱ 35 min · equipos

Simula un día completo de operaciones en la tienda escolar. El sistema ya tiene las tablas clientes, categorias, productos, pedidos y detalle_pedido creadas en BD·106. Realiza las siguientes operaciones en el orden correcto:

  • INSERT: llega un nuevo cliente, Valentina Ruiz.
  • INSERT: Valentina hace un pedido con 2 productos.
  • UPDATE: el precio de la Gaseosa sube de 3500 a 4000.
  • UPDATE: se vendieron 5 Empanadas, así que la cantidad baja de 30 a 25.
  • DELETE: se agotó el Café (cantidad = 0). Borra el producto.
  • INSERT: llega un nuevo producto, Jugo de mango, en la categoría Bebidas.
  • Verifica con SELECT el estado final de todas las tablas.
✏️ Espacio de borrador del equipo: script completo con todas las operaciones.
💡 Pista

Recuerda el orden: INSERT va padre → hijo (cliente antes que pedido, categoría antes que producto). DELETE va hijo → padre (si necesitas borrar una categoría, primero borra sus productos). Y para cada UPDATE o DELETE, escribe primero el SELECT de verificación.

🔍 Solución completa 
-- ═══════════════════════════════════════════════════
-- UN DÍA EN LA TIENDA ESCOLAR
-- ═══════════════════════════════════════════════════

-- 1. INSERT: nuevo cliente
INSERT INTO clientes (nombre, telefono)
VALUES ('Valentina Ruiz', '310-111-2222');   -- id = 1

-- 2. INSERT: pedido del cliente 1
INSERT INTO pedidos (cliente_id, total)
VALUES (1, 6000);   -- id = 1

-- 3. INSERT: detalle del pedido
INSERT INTO detalle_pedido (pedido_id, producto_id, cantidad, precio_unitario)
VALUES (1, 1, 1, 3500);   -- Gaseosa

INSERT INTO detalle_pedido (pedido_id, producto_id, cantidad, precio_unitario)
VALUES (1, 2, 1, 2500);   -- Empanada

-- 4. UPDATE: subir precio de la Gaseosa
SELECT * FROM productos WHERE id = 1;   -- verificar
UPDATE productos SET precio = 4000 WHERE id = 1;

-- 5. UPDATE: restar 5 Empanadas del inventario
SELECT * FROM productos WHERE id = 2;   -- verificar
UPDATE productos SET cantidad = cantidad - 5 WHERE id = 2;

-- 6. DELETE: borrar el Café (cantidad = 0)
SELECT * FROM productos WHERE nombre = 'Café';   -- verificar
DELETE FROM productos WHERE nombre = 'Café';

-- 7. INSERT: nuevo producto
INSERT INTO productos (nombre, categoria_id, precio, cantidad)
VALUES ('Jugo de mango', 1, 3000, 22);

-- 8. Verificar el estado final
SELECT * FROM clientes;
SELECT * FROM pedidos;
SELECT * FROM detalle_pedido;
SELECT * FROM productos;

Mini glosario de esta entrega

Consulta rápida
CRUD
Acrónimo de Create, Read, Update, Delete. Las cuatro operaciones fundamentales sobre los datos.
INSERT
Comando DML para agregar nuevas filas a una tabla.
UPDATE
Comando DML para modificar filas existentes. Siempre debe llevar WHERE.
DELETE
Comando DML para eliminar filas existentes. Siempre debe llevar WHERE.
TRUNCATE TABLE
Vacía una tabla completamente y reinicia el contador IDENTITY. No se puede filtrar con WHERE.
BEGIN TRAN
Inicia una transacción: agrupa varias operaciones en una sola unidad atómica.
COMMIT
Confirma los cambios de una transacción. Ya no se pueden deshacer.
ROLLBACK
Deshace todos los cambios de una transacción desde el BEGIN TRAN.
