02

Parte 1: Normalizar hasta 3FN

⏱ 45 min · aplica BD·102
1

Identifica las entidades

Pregúntate: ¿de qué "cosas" se habla en esta tabla? Hay datos de dueños, de mascotas, de servicios, de veterinarios y de citas. Cada una es una entidad y merece su propia tabla.

2

Identifica las dependencias

  • Los datos del dueño (nombre, teléfono, correo) dependen del dueño, no de la cita.
  • Los datos de la mascota (nombre, especie, edad) dependen de la mascota.
  • Los datos del servicio (nombre, precio) dependen del servicio.
  • Los datos del veterinario (nombre, especialidad) dependen del veterinario.
  • La fecha de la cita depende de la cita misma.
3

Diseña las tablas normalizadas

Basándote en las dependencias, deberías llegar a estas 5 tablas:

DUEÑOS

  • PK id
  • nombre
  • telefono
  • correo
→dueño_id

MASCOTAS

  • PK id
  • nombre
  • especie
  • edad
  • FK dueño_id
→mascota_id

CITAS

  • PK id
  • fecha
  • FK mascota_id
  • FK servicio_id
  • FK veterinario_id
←servicio_id

SERVICIOS

  • PK id
  • nombre
  • precio
←veterinario_id

VETERINARIOS

  • PK id
  • nombre
  • especialidad

Las relaciones

RelaciónTipoExplicación
DUEÑOS → MASCOTAS1:NUn dueño puede tener varias mascotas. Una mascota tiene un solo dueño.
MASCOTAS → CITAS1:NUna mascota puede tener varias citas. Una cita es de una sola mascota.
SERVICIOS → CITAS1:NUn servicio puede prestarse en muchas citas. Una cita tiene un solo servicio.
VETERINARIOS → CITAS1:NUn veterinario puede atender muchas citas. Una cita la atiende un solo veterinario.
💡 ¿Por qué CITAS no es N:M?Podrías pensar que CITAS es una tabla intermedia entre MASCOTAS y SERVICIOS (N:M). Pero en este caso, una cita tiene una fecha específica, un veterinario asignado y un solo servicio, así que es una entidad propia con identidad, no solo un puente. Por eso tiene su propio id como PK.
✅ Verifica tu normalización

Comprueba que tu diseño cumple 3FN:

  • ¿Cada tabla tiene una PK? ✔
  • ¿No hay celdas con múltiples valores? ✔
  • ¿Todos los campos no-clave dependen de la PK completa? ✔
  • ¿Ningún campo no-clave depende de otro campo no-clave? ✔
  • ¿El teléfono del dueño aparece una sola vez? ✔
  • ¿La especialidad del veterinario aparece una sola vez? ✔
  • ¿El precio del servicio aparece una sola vez? ✔

Si marcaste todo, tu diseño está en 3FN. Si no, revisa qué tabla te falta o qué campo está en la tabla equivocada.

03

Parte 2: Construir la base de datos con constraints

⏱ 60 min · aplica BD·103 a BD·106

Ahora escribe el script DDL completo. Incluye todas las constraints que aprendiste: PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, DEFAULT y CHECK.

  veterinaria_huellitas.sql
-- ═══════════════════════════════════════════════════
-- VETERINARIA HUELLITAS - SCRIPT DDL COMPLETO
-- ═══════════════════════════════════════════════════

-- Borrado seguro (hijo primero, padre después)
DROP TABLE IF EXISTS citas;
DROP TABLE IF EXISTS mascotas;
DROP TABLE IF EXISTS servicios;
DROP TABLE IF EXISTS veterinarios;
DROP TABLE IF EXISTS duenos;
GO

-- ═══════════════════════════════════════════════════
-- 1. DUEÑOS (padre de mascotas)
-- ═══════════════════════════════════════════════════
CREATE TABLE duenos (
    id       INT IDENTITY(1,1)
        CONSTRAINT PK_duenos PRIMARY KEY,
    nombre   VARCHAR(80) NOT NULL,
    telefono VARCHAR(20) NOT NULL
        CONSTRAINT UQ_duenos_telefono UNIQUE,
    correo   VARCHAR(120) NULL
);
GO

-- ═══════════════════════════════════════════════════
-- 2. MASCOTAS (hijo de dueños)
-- ═══════════════════════════════════════════════════
CREATE TABLE mascotas (
    id       INT IDENTITY(1,1)
        CONSTRAINT PK_mascotas PRIMARY KEY,
    nombre   VARCHAR(60) NOT NULL,
    especie  VARCHAR(40) NOT NULL
        CONSTRAINT CK_mascotas_especie CHECK (especie IN ('Perro','Gato','Ave','Otro')),
    edad     INT NULL
        CONSTRAINT CK_mascotas_edad CHECK (edad >= 0),
    dueño_id INT NOT NULL,

    CONSTRAINT FK_mascotas_dueno
        FOREIGN KEY (dueño_id) REFERENCES duenos(id)
);
GO

-- ═══════════════════════════════════════════════════
-- 3. SERVICIOS (padre de citas)
-- ═══════════════════════════════════════════════════
CREATE TABLE servicios (
    id     INT IDENTITY(1,1)
        CONSTRAINT PK_servicios PRIMARY KEY,
    nombre VARCHAR(80) NOT NULL
        CONSTRAINT UQ_servicios_nombre UNIQUE,
    precio DECIMAL(10,2) NOT NULL
        CONSTRAINT CK_servicios_precio CHECK (precio > 0)
);
GO

-- ═══════════════════════════════════════════════════
-- 4. VETERINARIOS (padre de citas)
-- ═══════════════════════════════════════════════════
CREATE TABLE veterinarios (
    id           INT IDENTITY(1,1)
        CONSTRAINT PK_veterinarios PRIMARY KEY,
    nombre       VARCHAR(80) NOT NULL,
    especialidad VARCHAR(60) NULL
);
GO

-- ═══════════════════════════════════════════════════
-- 5. CITAS (hijo de mascotas, servicios y veterinarios)
-- ═══════════════════════════════════════════════════
CREATE TABLE citas (
    id             INT IDENTITY(1,1)
        CONSTRAINT PK_citas PRIMARY KEY,
    fecha          DATE NOT NULL
        CONSTRAINT DF_citas_fecha DEFAULT GETDATE(),
    mascota_id     INT NOT NULL,
    servicio_id    INT NOT NULL,
    veterinario_id INT NOT NULL,

    CONSTRAINT FK_citas_mascota
        FOREIGN KEY (mascota_id) REFERENCES mascotas(id),
    CONSTRAINT FK_citas_servicio
        FOREIGN KEY (servicio_id) REFERENCES servicios(id),
    CONSTRAINT FK_citas_veterinario
        FOREIGN KEY (veterinario_id) REFERENCES veterinarios(id)
);
GO
💡 Checklist de constraintsAntes de continuar, verifica que tu script tiene:
  • PK en todas las tablas (IDENTITY).
  • FK en mascotas (dueño_id) y en citas (mascota_id, servicio_id, veterinario_id).
  • UNIQUE en telefono del dueño y nombre del servicio.
  • NOT NULL en los campos obligatorios.
  • DEFAULT en fecha de la cita (GETDATE()).
  • CHECK en especie (lista válida), edad (>= 0) y precio (> 0).
