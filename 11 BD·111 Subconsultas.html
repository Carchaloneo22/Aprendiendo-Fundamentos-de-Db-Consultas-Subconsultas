01

¿Qué es una subconsulta?

⏱ 15 min lectura

Imagina esta pregunta del dueño de la veterinaria:

"¿Qué servicios cuestan más que el precio promedio de todos los servicios?"

Para responderla necesitas dos pasos:

  1. Primero calcular el promedio: AVG(precio) de todos los servicios.
  2. Después filtrar los servicios cuyo precio sea mayor que ese número.

El problema: no sabes cuál es el promedio hasta ejecutar la primera consulta. Aquí es donde la subconsulta entra: la primera consulta vive dentro de la segunda.

  primera_subconsulta.sql
SELECT nombre, precio
FROM servicios
WHERE precio > (SELECT AVG(precio) FROM servicios);
🧠 Cómo se ejecutaSQL Server resuelve de adentro hacia afuera: primero calcula AVG(precio) (supongamos que da 88750), y luego ejecuta la consulta exterior como si dijera WHERE precio > 88750.

La regla de oro

  • Toda subconsulta va entre paréntesis.
  • Una subconsulta es un SELECT completo (puede tener WHERE, GROUP BY, etc.).
  • Puede ir en cuatro lugares: WHERE, FROM, SELECT y HAVING.
  • Según cuántos valores devuelve, se llama escalar (1 valor), de columna (1 columna) o de tabla (filas y columnas).

02

Subconsultas escalares: un solo valor

⏱ 25 min práctica

Una subconsulta escalar devuelve exactamente un valor (una fila, una columna). Se compara con operadores normales: = > < >= <= <>.

Ejemplos con la veterinaria

Ejemplo 1: servicios más caros que el promedio 
SELECT nombre, precio
FROM servicios
WHERE precio > (SELECT AVG(precio) FROM servicios);
Ejemplo 2: mascotas más jóvenes que el promedio de edad 
SELECT nombre, edad
FROM mascotas
WHERE edad < (SELECT AVG(edad) FROM mascotas);
Ejemplo 3: el servicio más caro (usando MAX) 
-- Todos los datos del servicio más caro
SELECT *
FROM servicios
WHERE precio = (SELECT MAX(precio) FROM servicios);
Ejemplo 4: dueños con más mascotas que el promedio 
-- Primero cuenta mascotas por dueño, luego compara con el promedio
SELECT d.nombre, COUNT(m.id) AS total_mascotas
FROM duenos d
INNER JOIN mascotas m ON m.dueño_id = d.id
GROUP BY d.nombre
HAVING COUNT(m.id) > (SELECT AVG(total) FROM (SELECT COUNT(*) AS total FROM mascotas GROUP BY dueño_id) x);
💡 NotaEste ejemplo combina una subconsulta en HAVING con una tabla derivada anidada. No te preocupes si se ve complejo: lo desarmamos en la Unidad 04.
Ejemplo 5: citas posteriores a la primera cita registrada 
SELECT fecha, mascota_id
FROM citas
WHERE fecha > (SELECT MIN(fecha) FROM citas);
🚨 CuidadoSi la subconsulta escalar devuelve más de una fila, SQL Server lanza un error: "Subquery returned more than 1 value". Si necesitas comparar contra varios valores, usa IN (Unidad 03).
03

IN, ANY y ALL: subconsultas que devuelven listas

⏱ 30 min práctica

Cuando la subconsulta devuelve varios valores, no puedes usar =. Usas IN para "está en la lista", ANY para "cumple con al menos uno" y ALL para "cumple con todos".

IN: "está en la lista"

Ejemplo 1: mascotas que han tenido al menos una cita 
SELECT nombre
FROM mascotas
WHERE id IN (SELECT DISTINCT mascota_id FROM citas);

La subconsulta devuelve una lista de ids de mascotas con citas (por ejemplo: 1, 2, 3, 4, 5). La consulta exterior muestra las mascotas cuyo id está en esa lista.

Ejemplo 2: dueños que tienen mascotas 
SELECT nombre
FROM duenos
WHERE id IN (SELECT dueño_id FROM mascotas);
Ejemplo 3: servicios que se prestaron el 2026-09-01 
SELECT nombre, precio
FROM servicios
WHERE id IN (SELECT servicio_id FROM citas WHERE fecha = '2026-09-01');
Ejemplo 4: veterinarios que atendieron una cirugía 
-- Primero encuentra el id del servicio 'Cirugía'
SELECT nombre, especialidad
FROM veterinarios
WHERE id IN (SELECT veterinario_id FROM citas
              WHERE servicio_id = (SELECT id FROM servicios WHERE nombre = 'Cirugía'));

Aquí hay dos subconsultas anidadas: la interior encuentra el id de Cirugía, la intermedia encuentra los veterinarios que la atendieron, y la exterior muestra sus datos.

NOT IN: "NO está en la lista"

Ejemplo 5: mascotas que NUNCA han tenido citas 
SELECT nombre
FROM mascotas
WHERE id NOT IN (SELECT mascota_id FROM citas);

ANY y ALL

Ejemplo 6: servicios más caros que ALGÚN servicio prestado el día 1 
-- ANY: basta con ser mayor que uno de la lista
SELECT nombre, precio
FROM servicios
WHERE precio > ANY (SELECT s.precio FROM servicios s
                     INNER JOIN citas c ON c.servicio_id = s.id
                     WHERE c.fecha = '2026-09-01');
Ejemplo 7: servicios más caros que TODOS los del día 1 
-- ALL: debe ser mayor que cada uno de la lista
SELECT nombre, precio
FROM servicios
WHERE precio > ALL (SELECT s.precio FROM servicios s
                     INNER JOIN citas c ON c.servicio_id = s.id
                     WHERE c.fecha = '2026-09-01');
OperadorSignificadoEjemplo
x IN (lista)x es igual a algún valor de la listaid IN (1, 3, 5)
x NOT IN (lista)x no es igual a ningún valorid NOT IN (2, 4)
x > ANY (lista)x es mayor que el mínimo de la listaprecio > ANY (100, 200)
x > ALL (lista)x es mayor que el máximo de la listaprecio > ALL (100, 200)
🚨 Cuidado con NOT IN y NULLSi la subconsulta de NOT IN devuelve algún NULL, el resultado completo queda vacío (porque x NOT IN (1, NULL) nunca puede ser verdadero). Si la columna puede tener NULL, filtra dentro de la subconsulta: WHERE columna IS NOT NULL, o usa NOT EXISTS (Unidad 05).
04

Tablas derivadas: subconsultas en el FROM

⏱ 25 min práctica

Una subconsulta en el FROM se comporta como una tabla virtual que solo existe durante la consulta. Se llama tabla derivada y siempre necesita un alias.

  sintaxis_derivada.sql
SELECT columnas
FROM (SELECT ... FROM ... GROUP BY ...) AS alias
WHERE ...;

Ejemplos con la veterinaria

Ejemplo 1: dueños con más de 1 mascota 
-- La tabla derivada cuenta mascotas por dueño;
-- la consulta exterior filtra los que tienen más de 1
SELECT x.dueño_id, x.total_mascotas
FROM (SELECT dueño_id, COUNT(*) AS total_mascotas
      FROM mascotas
      GROUP BY dueño_id) AS x
WHERE x.total_mascotas > 1;
Ejemplo 2: promedio de mascotas por dueño (sobre la tabla derivada) 
-- Ahora calculamos el promedio DE LOS TOTALES
SELECT AVG(x.total_mascotas) AS promedio_mascotas_por_dueno
FROM (SELECT dueño_id, COUNT(*) AS total_mascotas
      FROM mascotas
      GROUP BY dueño_id) AS x;
Ejemplo 3: veterinarios con más de 3 citas 
SELECT x.veterinario_id, x.total_citas
FROM (SELECT veterinario_id, COUNT(*) AS total_citas
      FROM citas
      GROUP BY veterinario_id) AS x
WHERE x.total_citas > 3;
Ejemplo 4: tabla derivada unida con JOIN a una tabla real 
-- Muestra el NOMBRE del dueño junto con su total de mascotas
SELECT d.nombre AS dueño, x.total_mascotas
FROM duenos d
INNER JOIN (SELECT dueño_id, COUNT(*) AS total_mascotas
            FROM mascotas
            GROUP BY dueño_id) AS x ON x.dueño_id = d.id;

Esto es poderoso: la tabla derivada x se une a la tabla real duenos como si fuera una tabla más.

Ejemplo 5: el total facturado por servicio, ordenado 
SELECT x.servicio_id, s.nombre, x.veces, x.total
FROM (SELECT servicio_id, COUNT(*) AS veces, SUM(servicio_id) AS total
      FROM citas GROUP BY servicio_id) AS x
INNER JOIN servicios s ON s.id = x.servicio_id
ORDER BY x.veces DESC;
💡 ¿Cuándo usar tabla derivada?Cuando necesitas filtrar o calcular sobre el resultado de un GROUP BY y HAVING se queda corto, o cuando quieres reutilizar un resultado agregado en varios lugares de la consulta. También es útil para "aplanar" consultas muy anidadas.
05

EXISTS y NOT EXISTS: ¿hay alguna fila?

⏱ 25 min práctica

EXISTS no devuelve datos: devuelve verdadero o falso. Responde a la pregunta "¿existe al menos una fila que cumpla esta condición?". Es la herramienta ideal para preguntas de existencia.

  sintaxis_exists.sql
SELECT columnas
FROM tabla_exterior e
WHERE EXISTS (SELECT 1 FROM tabla_interior i WHERE i.fk = e.pk);

Ejemplos con la veterinaria

Ejemplo 1: dueños que tienen al menos una mascota 
SELECT d.nombre
FROM duenos d
WHERE EXISTS (SELECT 1 FROM mascotas m WHERE m.dueño_id = d.id);

Para cada dueño, la subconsulta pregunta: "¿hay alguna mascota con este dueño_id?". Si hay al menos una, el dueño aparece en el resultado.

Ejemplo 2: mascotas que han tenido al menos una cita 
SELECT m.nombre
FROM mascotas m
WHERE EXISTS (SELECT 1 FROM citas c WHERE c.mascota_id = m.id);
Ejemplo 3: servicios que se han prestado al menos una vez 
SELECT s.nombre, s.precio
FROM servicios s
WHERE EXISTS (SELECT 1 FROM citas c WHERE c.servicio_id = s.id);
Ejemplo 4: veterinarios que atendieron al menos una cirugía 
SELECT v.nombre, v.especialidad
FROM veterinarios v
WHERE EXISTS (SELECT 1 FROM citas c
               INNER JOIN servicios s ON s.id = c.servicio_id
               WHERE c.veterinario_id = v.id AND s.nombre = 'Cirugía');

NOT EXISTS: los que NO tienen

Ejemplo 5: dueños SIN mascotas 
SELECT d.nombre
FROM duenos d
WHERE NOT EXISTS (SELECT 1 FROM mascotas m WHERE m.dueño_id = d.id);
Ejemplo 6: mascotas SIN citas 
SELECT m.nombre
FROM mascotas m
WHERE NOT EXISTS (SELECT 1 FROM citas c WHERE c.mascota_id = m.id);
Ejemplo 7: servicios que NUNCA se prestaron 
SELECT s.nombre
FROM servicios s
WHERE NOT EXISTS (SELECT 1 FROM citas c WHERE c.servicio_id = s.id);

EXISTS vs IN vs LEFT JOIN + IS NULL

La pregunta "dueños con mascotas" se puede resolver de tres formas. Mira la equivalencia:

EnfoqueConsulta
EXISTSWHERE EXISTS (SELECT 1 FROM mascotas m WHERE m.dueño_id = d.id)
INWHERE d.id IN (SELECT dueño_id FROM mascotas)
JOININNER JOIN mascotas m ON m.dueño_id = d.id (con DISTINCT si hace falta)
🤓 ¿Cuál es mejor?Las tres son correctas. EXISTS suele ser la más rápida cuando la tabla interior es grande, porque deja de buscar apenas encuentra la primera coincidencia. IN es más legible para listas pequeñas. JOIN es mejor cuando necesitas columnas de la segunda tabla en el resultado. En SQL Server moderno, el optimizador suele elegir el mismo plan para las tres.
06

Subconsultas correlacionadas: dependen de cada fila

⏱ 30 min práctica

Una subconsulta normal se ejecuta una sola vez y su resultado se usa para toda la consulta. Una subconsulta correlacionada se ejecuta una vez por cada fila de la consulta exterior, porque hace referencia a una columna de esa fila exterior.

La señal para reconocerla: la subconsulta usa una columna de la tabla exterior (por ejemplo, WHERE m.dueño_id = d.id, donde d viene de afuera).

Ejemplos con la veterinaria

Ejemplo 1: dueños con más mascotas que el dueño promedio... por fila 
-- Para CADA dueño, cuenta cuántas mascotas tiene
SELECT d.nombre,
       (SELECT COUNT(*) FROM mascotas m WHERE m.dueño_id = d.id) AS total_mascotas
FROM duenos d;

La subconsulta se ejecuta una vez por cada dueño: primero para Ana, luego para Bruno, luego para Carla... El alias d de afuera es la correlación.

Ejemplo 2: mascotas con más citas que la mascota promedio 
-- Subconsulta correlacionada dentro de otra subconsulta escalar
SELECT m.nombre
FROM mascotas m
WHERE (SELECT COUNT(*) FROM citas c WHERE c.mascota_id = m.id) >
      (SELECT AVG(total) FROM (SELECT COUNT(*) AS total FROM citas GROUP BY mascota_id) x);
Ejemplo 3: la cita más reciente de cada mascota 
-- Para cada mascota, muestra solo su cita más reciente
SELECT c.*
FROM citas c
WHERE c.fecha = (SELECT MAX(c2.fecha) FROM citas c2 WHERE c2.mascota_id = c.mascota_id);

Este es un patrón clásico: para cada fila de citas, la subconsulta busca el máximo de fecha de esa misma mascota. Solo se conservan las filas donde la fecha coincide con el máximo.

Ejemplo 4: el servicio más caro prestado por cada veterinario 
SELECT v.nombre AS veterinario,
       (SELECT MAX(s.precio) FROM citas c
        INNER JOIN servicios s ON s.id = c.servicio_id
        WHERE c.veterinario_id = v.id) AS servicio_mas_caro
FROM veterinarios v;

Correlacionadas con EXISTS

En realidad, todos los EXISTS de la Unidad 05 son correlacionados: la subconsulta siempre referencia la tabla exterior. La diferencia es que EXISTS solo pregunta por existencia, mientras que las correlacionadas de esta unidad devuelven valores concretos (contar, máximo, promedio...).

⚠️ RendimientoLas subconsultas correlacionadas se ejecutan una vez por fila exterior. Con 1000 dueños, la subconsulta corre 1000 veces. Para pocos datos está bien; para millones de filas, a veces conviene reescribirla como JOIN + GROUP BY. En este curso no optimizaremos, pero tenlo presente.
07

Subconsultas en el SELECT y comparación final con JOIN

⏱ 25 min práctica

Una subconsulta puede ir en la lista del SELECT como si fuera una columna calculada. Debe ser escalar (devolver un solo valor por fila).

Ejemplos

Ejemplo 1: cada servicio con la diferencia frente al promedio 
SELECT nombre,
       precio,
       precio - (SELECT AVG(precio) FROM servicios) AS diferencia_vs_promedio
FROM servicios;
Ejemplo 2: cada dueño con su total de mascotas como columna 
SELECT d.nombre,
       (SELECT COUNT(*) FROM mascotas m WHERE m.dueño_id = d.id) AS total_mascotas
FROM duenos d;
Ejemplo 3: cada cita con el nombre de la mascota (versión subconsulta) 
SELECT c.fecha,
       (SELECT m.nombre FROM mascotas m WHERE m.id = c.mascota_id) AS mascota
FROM citas c;

JOIN vs subconsulta: el mismo problema, dos caminos

Pregunta: "mascotas que han tenido citas". Mira las dos soluciones lado a lado:

CON JOIN (BD·110)
SELECT DISTINCT m.nombre
FROM mascotas m
INNER JOIN citas c
  ON c.mascota_id = m.id;
CON SUBCONSULTA (BD·111)
SELECT m.nombre
FROM mascotas m
WHERE m.id IN (
  SELECT mascota_id FROM citas);

¿Cuándo usar cada una?

SituaciónMejor opciónPor qué
Necesitas columnas de ambas tablas en el resultadoJOINLa subconsulta escalar en SELECT es más limitada.
Solo necesitas saber si existe correspondenciaEXISTS / INMás claro y a veces más rápido.
Comparas contra un agregado (promedio, máximo)SubconsultaJOIN no puede calcular el agregado "global" fácilmente.
Necesitas el "máximo por grupo"Correlacionada o tabla derivadaJOIN simple no resuelve el "por cada uno".
Unes 4-5 tablasJOINMás legible que anidar subconsultas.
💡 Regla prácticaSi la pregunta dice "junto con", "y su..." → JOIN. Si dice "más que el promedio", "que tienen...", "los que nunca..." → subconsulta. En la práctica profesional usarás ambas constantemente, a veces mezcladas en la misma consulta.

🏆 Reto final: genera un reporte con cada dueño, su número de mascotas, su número total de citas y su gasto total. Incluye los dueños sin mascotas (todo en 0). Usa subconsultas en el SELECT.

Ver solución
SELECT d.nombre,
       (SELECT COUNT(*) FROM mascotas m WHERE m.dueño_id = d.id) AS total_mascotas,
       (SELECT COUNT(*) FROM citas c
        INNER JOIN mascotas m ON m.id = c.mascota_id
        WHERE m.dueño_id = d.id) AS total_citas,
       ISNULL((SELECT SUM(s.precio) FROM citas c
        INNER JOIN mascotas m ON m.id = c.mascota_id
        INNER JOIN servicios s ON s.id = c.servicio_id
        WHERE m.dueño_id = d.id), 0) AS gasto_total
FROM duenos d;

Glosario de esta entrega

Consulta rápida
Subconsulta
Un SELECT completo dentro de otro SELECT, BETWEEN, WHERE, FROM o HAVING. Siempre va entre paréntesis.
Subconsulta escalar
Devuelve un único valor (una fila, una columna). Se compara con =, >, <, etc.
Tabla derivada
Subconsulta en el FROM que actúa como tabla virtual. Requiere un alias.
Subconsulta correlacionada
Referencia una columna de la consulta exterior; se ejecuta una vez por cada fila exterior.
EXISTS
Operador que devuelve verdadero si la subconsulta produce al menos una fila.
IN
Operador que verifica si un valor pertenece a la lista devuelta por una subconsulta.
ANY / ALL
Operadores que comparan un valor contra alguno (ANY) o todos (ALL) los valores de una lista.
Consulta exterior
La consulta que contiene a la subconsulta. Se evalúa después de la subconsulta (salvo en correlacionadas).
